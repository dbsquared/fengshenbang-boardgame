# 《封神榜》页游 · 设计文档

> 版本：v0.1（单章可玩原型阶段）
> 日期：2026-08-10
> 目标：将实体桌游《封神榜》转化为可在浏览器直接游玩的网页游戏。
> 本文档与 `资料/封神榜规则书解析.md` 配套使用，后者为规则唯一依据。

---

## 1. 项目目标与 MVP 范围

### 1.1 总体愿景
把这款 1–4 人合作战役桌游，做成一个**分章节、可逐步扩展**的网页游戏。最终形态应支持 12 个章节战役、卡组继承、多人合作/在线对战。

### 1.2 本阶段 MVP（第一版交付物）
根据用户决策，第一版聚焦：

| 维度 | 本版决策 |
|------|----------|
| 范围 | **单章可玩原型**：仅做第 1 章《地牢》 |
| 技术 | **纯前端** HTML + CSS + 原生 JS（SVG 渲染地图），无需服务器 |
| 美术 | **中国古风 / 水墨**风格（占位图即可，逻辑优先） |
| 交付 | 先出设计文档 + 可点击原型，确认方向后再迭代 |

### 1.3 本版明确不做（后续迭代）
- 多玩家热座 / 在线联机
- 法力五行系统（第三章后解锁，本版不含）
- 灵兽 / 同伴完整行动卡
- 卡组继承与战役进度存档（localStorage 可后续加）
- 12 章其余章节地图与头目机制
- 真人手绘美术资源（先用 CSS/SVG 占位）

---

## 2. 技术选型

| 项 | 选择 | 理由 |
|----|------|------|
| 语言 | HTML5 + 原生 JavaScript（ES2020） | 零构建、双击即玩、易分享 |
| 地图渲染 | **SVG**（非 Canvas） | 六边形格子点击命中简单，水墨描边易实现，DOM 事件友好 |
| 样式 | 原生 CSS（含 CSS 变量、渐变、滤镜） | 实现宣纸质感、墨色、印章红 |
| 状态管理 | 单一 `GameState` 对象 + 纯函数 reducer 风格 | 便于测试与后续接入后端/联机 |
| 存档 | 本版暂用内存；后续可加 `localStorage` | 轻量 |
| 依赖 | 无第三方库 | 纯前端、零安装 |

> 后续若要做联机/复杂动画，可平滑迁移到 Vite + TypeScript，但本版保持极简。

## 3. 整体架构

```
封神榜/
├─ 资料/封神榜规则书解析.md      # 规则依据（已生成）
├─ 设计文档.md                   # 本文档
└─ prototype/                    # 第一版可玩原型
   ├─ index.html                 # 入口
   ├─ style.css                  # 水墨风样式
   └─ game.js                    # 游戏逻辑（状态机 + 渲染 + 交互）
```

`game.js` 内部模块划分（同一文件内按区域组织）：
1. **数据层**：`GameState`、角色/敌人/卡牌/地图的工厂与初始数据
2. **规则层**：六边形坐标数学、移动可达性(BFS)、战斗结算、敌方 AI、胜负判定
3. **交互层**：阶段推进、卡牌选择/打出、单位选中、点击地图
4. **渲染层**：SVG 地图绘制、面板/手牌/日志渲染
5. **主循环**：`render()` 统一重绘，`handleXxx()` 事件处理

## 4. 数据模型（草案）

```js
GameState = {
  chapter: 1,
  phase: 'move' | 'attack' | 'interact' | 'enemy',  // 移动/出招/交互/敌方行动
  turn: 1,
  players: [ Player ],          // 本版 1 名（单人模式）
  npcs: [ Npc ],                // 本版 姬昌
  enemies: [ Enemy ],
  map: { cells: Map<key,{q,r,type,feature}>, ... },
  log: [ string ],
  selected: { card, unit },     // 当前选中的卡/单位
  status: 'playing' | 'win' | 'lose'
}

Player = {
  id, name, char, pos:{q,r},
  panel: { wu, nei, ling, ti, hp, maxHp, move, moveLeft, neiLeft },
  hand: [ Card ], discard: [ Card ],
  equipment: { weapon, armor, treasure },
  status: { stun:bool, poison:int },
  alive: bool, isSpirit: bool
}

Enemy = {
  id, name, kind:'minion'|'boss', color, pos:{q,r},
  hp, maxHp, atk, range, reviveAtExit:bool, alive:bool
}

Card = { id, name, cost, weapon, effect:{dmg, range, aoe, type} }
```

> 属性数值（武力/内力/生命等）本版用**代表性示例值**，界面标注"示例"，待按实物卡牌校准。

## 5. 核心循环（四阶段）

回合严格按 `移动 → 出招 → 交互 → 敌方行动` 推进，每阶段有"结束本阶段"按钮进入下一阶段，敌方阶段结束后自动回到下一名玩家（本版单人即回到自己）并重置移动力/内力。

| 阶段 | 玩家能做什么 | 原型实现要点 |
|------|--------------|--------------|
| 移动 | 点击高亮格，消耗移动力移动 | BFS 计算可达格，障碍/单位阻挡 |
| 出招 | 选招式卡 → 选目标敌人打出，消耗内力 | 内力上限校验；应对卡(0)机制预留 |
| 交互 | 本版：护送姬昌（玩家相邻时姬昌向出口移动一步） | 简化版同伴行动 |
| 敌方行动 | 自动 | 敌方 AI：向最近目标移动，进入射程则攻击 |

## 6. 第 1 章《地牢》落地方案

### 6.1 胜利 / 失败条件（忠于原规则）
- **胜利**：护送 **姬昌** 到达任意**出口格**（原规则：找到姬昌并保护他到达任意出口格）。
- **失败**：玩家生命归 0，或姬昌生命归 0（保护失败）。
- 关卡内放置一名**头目**作为拦截障碍，击败头目也可作为**备选胜利**（便于演示战斗），但主线以护送为准。

### 6.2 地图（示例布局）
- 六边形网格（约 9×8），含：
  - 玩家起始格（1 个）
  - 姬昌起始格
  - 出口格（2–3 个，高亮发光）
  - 敌方小兵刷新点（出口格附近，体现"小兵在出口格复活"）
  - 头目格
  - 若干障碍格（墙）
  - 1–2 个叹号标记（治疗/宝箱效果）
- 注：精确格子排布为原型示意，非实物版图还原。

### 6.3 敌方 AI（原型版）
- 小兵：每敌方回合向最近的（玩家/姬昌）移动 1 格（绕开障碍），相邻则攻击（扣血）。
- 头目：移动较慢、攻击高，作为拦截。
- 复活：小兵在出口格死亡后，下一敌方回合于出口格复活（体现原机制）。

### 6.4 交互阶段（护送）
- 玩家在姬昌相邻格时，交互阶段可触发"护送"：姬昌沿最短路径向最近出口移动 1 格。
- 玩家需沿途清除/引开敌人，保护姬昌血量。

## 7. 美术方向（水墨风）

- **底色**：宣纸米黄 `#ece3d0` 偏暗，或深墨底 `#1a1a1a` + 浅墨 UI（依 IDE 暗色主题，本版用深底浅字）。
- **地图格**：六边形描淡墨边，障碍格填深墨/石青。
- **单位**：玩家=朱红圆+篆字；姬昌=青色；小兵=灰/按底色；头目=金/大。
- **出口**：朱红描边发光。
- **字体**：标题用衬线/楷体感（`KaiTi`, `STKaiti` 回退 `serif`）。
- **点缀**：右上角朱红印章"封神榜"，行动日志用竖排感。

> 本版全部为 CSS/SVG 占位，不引入图片资源；后续可替换为手绘 PNG/SVG。

## 9. 简化项与待校准清单

1. 角色/敌人**属性数值为示例**，需按实物卡牌核对（尤其各章敌人介绍卡、头目血量）。
2. 地图格子布局为**示意**，非实物版图还原；需拍照/测量真实版图坐标。
3. 招式卡效果做了**高度简化**（仅伤害/范围），未实现位移（飞跃/拉近/推远/旋转）、视野遮挡等细则。
4. 法力、灵兽、同伴完整行动卡、窥觑天机、配置卡牌规则均未实现（按路线图后续）。
5. 敌方 AI 为贪心最近目标，未实现"按立牌底色顺序""攻击范围内停止移动"等细则的完整还原。

> 校准方式：后续逐章读取对应规则书照片 + 实物卡牌，补充 `资料/` 下分章数据文件，再回填 `game.js` 数据层。
